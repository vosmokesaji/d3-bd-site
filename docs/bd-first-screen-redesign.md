# BD 首屏两列重构方案

更新日期：2026-08-31

## 1. 目标重新定义

“PC 首屏尽可能囊括”指首屏能快速回答构筑决策，不代表把所有完整详情缩小后塞进同一屏。首屏必须让玩家看清：

1. 当前 BD 的核心发动机和场景差异。
2. 身上穿了什么，以及选中装备在当前 BD 中承担什么作用。
3. 六个主动技能、四个被动和当前赛季魔方威能。
4. 当前巅峰阶段四个分类的首要投入。
5. 下一步深入查看完整装备、技能、魔方和评审细节的入口。

完整物品原始特效、全部词缀、获取方式和长篇策略属于第二层详情，不占据首屏主空间。

## 2. 当前方案需要纠正的问题

- 禁止再整体缩放包含文字和点击区域的纸娃娃。固定 `994x645` 画布缩放到 `0.62/0.56` 后，11-12px 文字实际只剩约 6-7px。
- 禁止用固定缩放比例配合 `overflow: hidden` 裁切纸娃娃；画布必须完整可见，点击区域与视觉位置一致。
- 首屏不再常驻完整游戏 Tooltip。它让 16px 长段装备特效压过真正重要的构筑原因。
- 构筑摘要不允许使用 8-10px 正文，也不允许通过固定高度和隐藏溢出吞掉信息。
- 不维持“纸娃娃 + 完整装备 Tooltip + 构筑指挥台”三列竞争宽度的布局。

## 3. 首屏布局

桌面采用两列：

```text
┌────────────── 标题、场景和巅峰切换 ──────────────┐
│                                                  │
│  完整可读的装备纸娃娃       构筑总览 / 装备作用   │
│  装备名保持正常字号         核心原理与场景差异     │
│  点击装备锁定选择           技能、被动、魔方摘要   │
│  底部显示关键属性           巅峰四项首要优先级     │
│                                                  │
└──────────────────────────────────────────────────┘
```

- 左列是首屏主视觉，完整展示纸娃娃、装备槽和可读装备名。
- 右列是分层信息面板，提供“构筑总览”和“装备作用”两个页签。
- 默认打开“构筑总览”。点击或键盘聚焦纸娃娃装备后，切换到“装备作用”并锁定当前装备。
- “装备作用”只显示装备名、部位、品质、当前 BD 作用、前三项词缀、镶嵌和完整物品详情入口。
- 完整技能、魔方、联动、随从、手法和评审模块继续保留在首屏下方。

## 4. 视觉和交互约束

- 首屏正文使用 13-14px，装备名和技能名使用 12-14px，辅助信息不得低于 11px。
- 纸娃娃视觉层可以响应式缩放，文字与交互层不得跟随 `transform` 缩小。
- 装备点击后保持选择，不使用悬停驱动详情。
- 右侧页签必须可通过键盘操作，并用 `aria-selected` 表达状态。
- 1280-1439px 桌面仍保持两列，但允许技能、被动和魔方摘要增加行数，不裁切内容。
- 手机端按“场景切换 → 纸娃娃 → 分层信息面板 → 完整模块”顺序单列展示。

## 5. 验收标准

1. `1280x800`、`1440x900`、`1920x1080` 下纸娃娃完整可见，没有左右裁切。
2. 首屏纸娃娃装备名、右侧构筑原因、技能、魔方和巅峰摘要均可直接阅读。
3. 不存在低于 11px 的首屏正文或通过整体缩放得到的等效小字号。
4. 点击任意装备后右侧稳定展示其 BD 作用，移动鼠标不会改变选择。
5. 首屏不再显示完整原始装备特效、全部获取方式和长词缀列表。
6. 右侧内容不依赖固定高度加 `overflow: hidden` 才能成立。
7. `390x844` 下没有页面级横向溢出，纸娃娃如需横向空间只在自身区域处理。

## 6. 实施顺序

1. 改为两列首屏，移除首屏完整装备 Tooltip。
2. 增加“构筑总览 / 装备作用”分层面板和点击锁定联动。
3. 拆开纸娃娃视觉层与文字交互层，修复裁切和等效小字号。
4. 统一首屏字号，调整桌面和手机断点。
5. 完成构建、回归测试和多分辨率视觉验收后，再更新本文件的完成状态。

当前状态：已完成。

完成结果：

- PC 首屏已改为纸娃娃与分层指挥台两列，常驻完整装备 Tooltip 已移除。
- 纸娃娃改为响应式几何定位，不再使用 `transform: scale(...)` 缩小文字和点击区域。
- “构筑总览 / 装备作用”页签已上线；点击装备会锁定当前选择，悬停其他装备不会改掉详情。
- `1280x800`、`1440x900`、`1920x1080` 已完成首屏视觉验收，纸娃娃、属性条和构筑摘要均在视口内。
- `390x844` 已确认无页面级横向溢出；纸娃娃仅在自身区域横向滚动。

## 7. 维护约束

- 装备加成始终位于纸娃娃左下视觉留白区，不再独立占用首屏高度。
- `head`、`shoulders`、`gloves`、`bracers`、`boots` 的装备图标可越出框体；该规则由 `art-overflow` 类声明，压缩或响应式调整不得覆盖。
- 纸娃娃内的宝石尺寸必须相对装备槽缩放，不能保留固定 `32px` 外框。
- 宝石框来自 `skill-overlays.png` 的原生 `32px` 精灵区域。纸娃娃缩放时，宝石框、宝石图和整张图集坐标必须按同一比例缩放；不得仅缩小容器或整张图集，否则会分别造成只剩宝石框一角或框体消失。
- 装备图必须保留原始 `64x128` 精灵比例，并沿用暴雪纸娃娃各槽位的裁切偏移；不得用 `object-fit: contain` 把原图压进装备框。`art-overflow` 槽位在这一规则下必须看得到越界图形。
- 暴雪官网 `hero-slots.css` 的真实基准是：装备精灵 `64x128`，项链 `52x52`，宝石框 `32x32`，宝石 `20x20`；头、肩、胸等槽位另有逐项偏移。本站以 `994px` 纸娃娃为坐标基准，用容器宽度单位同步缩放上述尺寸与偏移，禁止使用固定缩放档位。
- 本地腰带与戒指素材是已经裁成 `64x64` 的方图，不能再拉伸成官网 `64x128` 精灵，否则腰带会被裁空、戒指会纵向放大；胸甲素材顶部透明区只有 `14px`，使用对应的本地素材偏移。胸甲与腰带的槽位比 `64px` 素材更宽，必须先按官网的 `text-align: center` 居中素材，再叠加胸甲 `left: -1px` 的校正，不能把偏移直接当成素材起点。
- 宝石与宝石框沿用官网 `.sockets-wrapper` 的 `opacity: 0.8`，悬停、键盘聚焦或锁定装备时恢复为 `1`。
- 装备图片缩小时必须缩放位图内容本身。不得使用 `object-fit: none` 搭配缩小后的宽高，否则元素盒子变小但原始位图不会缩小，会造成装备看起来过大、位置和官网不一致。
- “装备作用”的词缀按数据顺序完整展示：普通情况四条，需要五条主词缀的装备展示五条。
